Add a server

Click below, log into Plex in the tab that opens, and approve access. ClipHanger picks up the resulting token and your server's host/port automatically — nothing to find, copy, paste or type.

or enter details manually

Open the Plex Web App (app.plex.tv), go to any movie → the ⋯ menu → Get Info → View XML (bottom-left). A new tab opens — the token is in that tab's address bar, not the page text, as the part after X-Plex-Token= (up to the next & if there is one).

Kodi's web server has to be turned on first, on the Kodi box itself: Settings → Services → Control → Allow remote control via HTTP. Username/password below are only needed if you also enabled "Require authentication" on that same screen — leave both blank otherwise. Note: Kodi only serves files inside a configured source — a movie it can play isn't necessarily one it will hand over for extraction.

Optional fallback for the "outside a configured source" problem above. If Kodi's web server refuses to serve a file (401) because it's outside a source, and ClipHanger happens to have its own access to the same media (e.g. the same NAS share mounted separately), it can read the file directly instead of giving up — but only for that one situation; every other item still goes through Kodi normally. Fill in the two paths below only if you want this fallback: the path prefix as Kodi's own library reports it, and the prefix ClipHanger should replace it with. Leave both blank to skip this — nothing changes if you do.

In Jellyfin, go to Dashboard → API Keys, click +, give it a name like "ClipHanger", and paste the key it generates below. Unlike Plex, this key is scoped to the server admin who created it and can be revoked from that same page at any time.

No server to talk to here — ClipHanger reads the file straight off a disk it already has access to (a NAS share mounted into this container, say) instead of streaming it from a media server over HTTP. Faster and more reliable when it's available, since there's no server-side session, auth, or transcode step to go wrong — but it only works for items a client explicitly resolves this way.

Use whatever your Plex/Kodi/Jellyfin server itself calls this file's folder (Plex's "View XML" → Part file=, Kodi's own library path, Jellyfin's file path) — not what you assume the real filesystem layout is. Don't have that handy yet? Leave it blank, add the server anyway (only ClipHanger's own path above is required), then generate a preview for one movie through it — this server's own card on this page will show the exact path that was attempted, with a button to adopt it. Every attempt fails until then, which is expected, not broken.

Retention

How long a finished job's still/clip and record stick around before being deleted automatically. ClipHanger keeps everything forever by default — set a number of hours here only if you want old jobs cleaned up on their own. Takes effect immediately, no restart needed.

Concurrency

How many jobs ClipHanger runs at once. Each one is a full ffmpeg decode, and this box may be serving media at the same time — running more jobs in parallel doesn't mean more finish sooner, it can just mean every job gets a smaller slice of the same CPU and takes longer. Auto by default — picks a limit from this host's CPU count. Takes effect on the next job pulled off the queue, no restart needed.

Clip duration

How long a generated clip runs, for any job that doesn't specify its own spanSeconds. A clip is a plain H.264 encode with no inter-frame compression, so file size scales roughly linearly with duration.

Playback speed

Plays back more of the scene in the same clip duration, by reading extra source and compressing its timeline — at 2x, a 20s clip actually covers 40s of the scene. A longer, meaningful moment can run a few minutes; 1x only shows a short slice of it. Unlike clip duration above, no client sends its own speed value on a job — this setting controls it for every client.

ffmpeg command preview

The actual command a job runs, given the clip duration and speed settings above. <...> marks the parts that vary per job (source URL, timestamp, output path).
